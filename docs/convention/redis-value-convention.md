# Redis Value 컨벤션

## 목적
- 서비스별 Redis 값 포맷 불일치로 인한 역직렬화 오류를 방지한다.
- 캐시 저장/조회 로직을 팀 공통 규칙으로 통일한다.

## 네이밍
- 문서/PR/리뷰에서 아래 용어를 사용한다.
  - `Redis Value 컨벤션`
  - `Redis 직렬화 규칙`

## 핵심 규칙
1. Redis value는 **JSON 문자열 1가지 포맷만** 사용한다.
2. `@class` 같은 타입 메타데이터에 의존하지 않는다.
3. 저장 시 객체를 JSON 문자열로 직렬화 후 저장한다.
4. 조회 시 JSON 문자열을 대상 DTO/VO 타입으로 역직렬화한다.
5. 레거시 포맷 호환 코드는 신규 개발에서 추가하지 않는다.

## 구현 규칙
- 키는 `RedisKeys`에서 중앙 관리한다.
- UTF-8 인코딩으로 저장/조회한다.
- TTL은 키 단위로 명시한다.
- 캐시 실패(직렬화/네트워크)는 비즈니스 실패로 전파하지 않고 로그 후 fallback 한다.

## 금지 사항
- `Object` 기반 다형 역직렬화 전제 설정 사용 금지
- 동일 키에 타입이 다른 값을 저장하는 방식 금지
- 기능별 임의 포맷(plain text, map, json 혼용) 금지

## 예시 정책 (user detail)
- key: `core:user:detail:v1:{userId}`
- value: `UserResponse`를 JSON 문자열로 직렬화한 값
- TTL: 120초

## 리뷰 체크리스트
- 저장 시 JSON 문자열만 쓰는가?
- 조회 시 명시 타입으로 파싱하는가?
- 동일 키의 value 타입이 환경별로 동일한가?
- 실패 시 fallback 정책(로그 + DB 조회)이 있는가?
